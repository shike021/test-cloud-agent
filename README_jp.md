# Web Arcade · ブラウザーだけで遊べるミニゲーム集

[简体中文](./README.md) · [English](./README_en.md) · 日本語 · [Español](./README_es.md)

ランタイム依存ゼロのフロントエンド専用ミニゲーム集です：**ゲームロビー + スネーク + 五目並べ + 2048 + 連連看**。ルールはユニットテスト可能なコアモジュールに閉じ込められており、デスクトップでもモバイルでもそのまま遊べます。

## クイックスタート

Node.js 20.10 以降が必要です（開発ツールチェーンでのみ使用し、ゲーム自体は Node.js に依存しません）。

```bash
git clone https://github.com/shike021/test-cloud-agent.git
cd test-cloud-agent
npm install
npm run dev            # ローカル静的サーバーを起動
```

<http://127.0.0.1:5173/> を開くとゲームロビーに入れます。

> ソースコードはネイティブの ES Modules を使用しています。ブラウザーは `file://` 経由でのモジュール読み込みを許可しないため、HTML ファイルを直接開かずに `npm run dev`（または任意の静的サーバー）からアクセスしてください。

配布可能な静的サイトが必要な場合は `npm run build` を実行してください。成果物は `dist/` に出力され、`npm run preview` でローカルにプレビューできます。

## ゲーム説明

### スネーク · Snake

リアルタイムの 1 人用ゲームです。固定ステップのロジックとフレーム間補間を組み合わせているため、マス単位のカクついた移動ではなく滑らかな連続移動になり、高精細ディスプレイにも対応します。

**操作**

| 操作             | キーボード                             | モバイル                               |
| ---------------- | -------------------------------------- | -------------------------------------- |
| 移動             | `↑` `↓` `←` `→` または `W` `A` `S` `D` | 画面上の方向キー、または盤面のスワイプ |
| 開始 / 一時停止  | `スペース` / `P`                       | 「開始」ボタン、または盤面のタップ     |
| リスタート       | `R` / `Enter`                          | 「リスタート」ボタン                   |
| 効果音の切り替え | `M`                                    | サウンドボタン                         |

**ルール**

- 赤い果実を食べると **10 点**を獲得し、体が 1 節伸びます。
- 通常の果実を 5 個食べるごとに金色の星が出現します。星は **50 点**になりますが体は伸びません。星には制限時間（外周のリング）があり、時間切れで消えます。
- 累計 **60 点**ごとにレベルが上がって移動速度が上がり、選択中の難易度の速度上限に達するまで加速します。
- 壁にぶつかるか自分の体を噛むとゲームオーバーです。「ワープモード」を有効にすると壁では死ななくなり、自分を噛んだ場合のみ終了します。
- 体が盤面をすべて埋めるとクリアです。
- 蛇はその場で反転できません（右に進んでいるときに「左」を押しても無効です）。素早い連続入力は順番にバッファーされ、後続のフレームで適用されるため入力が失われることはありません。

難易度はイージー / ノーマル / ハードの 3 段階でテンポを選べ、「ワープモード」は個別に有効化できます。

### 五目並べ · Gomoku

同一端末で遊ぶ 2 人対戦です。15×15 の交点、木目の盤面、星の位置、A–O / 1–15 の座標表示（非表示にも切り替え可能）を備えています。再描画は、着手・待った・ホバー・サイズ変更が発生したときだけ必要に応じて行われます。

**操作**

| 操作               | キーボード                                                | マウス / モバイル                |
| ------------------ | --------------------------------------------------------- | -------------------------------- |
| カーソル移動       | 盤面にフォーカス後 `↑` `↓` `←` `→` または `W` `A` `S` `D` | マウスホバーでプレビュー石を表示 |
| 着手               | `Enter` / `スペース`                                      | 交点をクリックまたはタップ       |
| 新規対局           | `N`                                                       | 「新規対局」ボタン               |
| 待った（元に戻す） | `U` / `Z`                                                 | 「待った」ボタン                 |
| 効果音の切り替え   | `M`                                                       | サウンドボタン                   |

**ルール**

- 黒と白が交互に交点へ石を置き、縦・横・斜めのいずれかに **5 つ以上**並べたほうが勝ちです（禁じ手はなく、長連も勝ちとして扱います）。
- 225 か所の交点がすべて埋まり、どちらも 5 つ並べられなかった場合は引き分けです。
- 最後の一手は赤い円で示されます。勝利時は並んだ石が金色でハイライトされ、勝利線が引かれます。
- 「待った」は直前の一手を取り消します。決め手を取り消した場合は、その対局の成績も併せて巻き戻されます。
- 「先手交替」を有効にすると、新規対局のたびに先手が入れ替わり、次局の色が記憶されます。

黒勝ち / 白勝ち / 引き分けの数は設定と一緒にローカルへ保存され、ワンクリックでまとめて消去できます。

### 2048

定番の 4×4 数字合成ゲームです。盤面は Canvas ではなく DOM のタイルで構成しています。タイルの行・列座標を CSS 変数に書き込み、移動・合成・出現のアニメーションはすべてスタイルシート側が担当するため、盤面はコンテナーに合わせて伸縮し、描画層がレイアウトを計測する必要がありません。

**操作**

| 操作         | キーボード                             | マウス / モバイル                      |
| ------------ | -------------------------------------- | -------------------------------------- |
| 移動         | `↑` `↓` `←` `→` または `W` `A` `S` `D` | 画面上の方向キー、または盤面のスワイプ |
| 新しいゲーム | `R`                                    | 「新しいゲーム」ボタン                 |
| 続けて挑戦   | `C` / `スペース`                       | 「続けて挑戦」ボタン                   |

**ルール**

- 1 回の移動ですべてのタイルが同じ方向へ寄ります。同じ数字どうしがぶつかると和になって合体し、その和が得点に加算されます。
- 1 回の移動で 1 つのタイルが合体できるのは 1 度だけです。`2 2 2 2` を左へ動かすと `4 4`、`2 2 4` は `8` ではなく `4 4` になります。合体は進行方向の端から順に処理されるため、`2 2 2` は左で `4 2`、右で `2 4` になります。
- 盤面が実際に変化した移動だけが手数に数えられ、空きマスに新しいタイルが 1 つ出現します（90% が **2**、10% が **4**）。
- **2048** を作れば勝利です。そこでやり直すことも、4096 以上を目指して続けることもできます。
- 盤面が埋まり、4 方向のいずれにも動かせなくなった時点で終了です。

得点・ハイスコア・最大タイル・手数はリアルタイムに表示され、ハイスコアはローカルに保存されてロビーのカードにも反映されます。

### 連連看 · Link Match

四川省スタイルの定番つなぎ消しです。盤面は DOM タイルで、選択・ヒント・接続線は CSS / SVG が担当します。コアは合法な折れ点だけを返し、ブラウザー API には触れません。

**操作**

| 操作                   | キーボード         | マウス / モバイル      |
| ---------------------- | ------------------ | ---------------------- |
| 牌を選ぶ               | フォーカス後 Enter | 牌をクリック / タップ  |
| ヒント                 | `H`                | 「ヒント」ボタン       |
| 待った                 | `U` / `Z`          | 「待った」ボタン       |
| このステージをやり直す | `R`                | 「やり直す」ボタン     |
| 次のステージ           | `N` / `Enter`      | 「次へ」ボタン         |
| 選択解除               | `Esc`              | 同じ牌をもう一度タップ |

**ルール**

- 同じ絵柄の牌を 2 枚選び、他の牌を通らず **直線 3 本以内**（折れ 0 / 1 / 2 回）で結べれば消えます。経路は盤の外側の空き枠を通っても構いません。
- すべて消すとクリアです。次のステージへ進むと盤面が大きくなり、絵柄も増えます。ステージ 1 はかんたん（6×8、8 種、時間制限なし、ヒント 5）、ステージ 2 はふつう（8×10、12 種、180 秒、ヒント 3）、ステージ 3 以降はむずかしい（10×12、16 種、カウントダウン、ヒント 1）。ステージ 4 以降は制限時間がさらに短くなり、最短 60 秒です。
- 時間切れや手詰まりは失敗です。やり直すと、そのステージ開始時点の得点に戻ります。開始難易度を変えると新しいランになります。
- 連続消去でコンボ点が入り、制限時間付きステージでは残り秒数もボーナスになります。ヒント回数は難易度が上がるほど減ります。

得点とハイスコアはリアルタイムに表示され、ハイスコアはローカルに保存されてロビーのカードにも反映されます。

### 共通の特徴

- **状態の永続化**：ハイスコア、対局成績、効果音のオン・オフ、各種設定は `localStorage` に保存され、プライベートモードなど書き込みできない環境では自動的にメモリー内保存へフォールバックします。4 つのゲームはそれぞれ別の名前空間（`snake-game` / `gomoku` / `game-2048` / `lianliankan`）を使うため、互いに干渉しません。
- **アクセシビリティと使い勝手**：セマンティックなマークアップ、`aria-live` による読み上げ、キーボードでフォーカスできるコントロール、`prefers-reduced-motion` への対応、タブ切り替え時の自動一時停止（スネーク）、盤面のテキスト説明（2048 / 連連看）。
- **ランタイム依存ゼロ**：ネイティブの HTML / CSS / ES Modules と Canvas 2D、Web Audio だけで構成しています。

### アーキテクチャのポイント

- **ルールと表示の分離**：`src/js/core/snake-game.js`、`src/js/gomoku/gomoku-game.js`、`src/js/game2048/core/game-2048.js`、`src/js/lianliankan/core/lianliankan-game.js` はブラウザー API に依存しないクラスです（スネーク、2048、連連看の乱数はコンストラクター引数で注入します）。そのためルールは Node.js 上で決定論的にテストできます。描画・入力・効果音・ストレージはそれぞれ独立しており、エントリーの `main.js` は組み立てと駆動だけを担当するので、ルールの変更が描画コードに波及しません。
- **複数の駆動方式**：スネークはリアルタイムゲームで、固定ステップのアキュムレーターが `tickIntervalMs` に従ってロジックを進め、各フレームでは `alpha`（次の tick までの進捗）を使って前後の状態を補間します。これによりリフレッシュレートの異なる端末でも同じ挙動になります。五目並べは入力があったときだけ変化するためアニメーションループを持たず、必要なときに 1 フレームだけ再描画します。2048 も同じくターン制ですが、アニメーションは DOM タイルが担います。コアが各タイルに安定した id と「移動前の位置」を持たせるので、描画層は要素を使い回し、移動と合体のアニメーションを CSS のトランジションに任せられます。連連看もターン制で、制限時間付きステージはエントリーが `requestAnimationFrame` から経過時間を `tick()` に渡します。接続の折れ点はコアが返し、SVG が線を描きます。
- **スタイルの階層化**：`base.css` がデザイン変数と各ページ共通のコンポーネント（ボタン、盤面枠、オーバーレイ、画面上の方向キーなど）を提供し、各ページのスタイルシートは `@import` で読み込んだうえで自身のレイアウトの差分だけを記述します。ビルド時に esbuild が `@import` をインライン化するため、最終的に各ページが読み込む CSS は 1 つだけになります。

## 開発用スクリプト

| コマンド               | 説明                                                                   |
| ---------------------- | ---------------------------------------------------------------------- |
| `npm run dev`          | ローカル静的サーバーを起動（既定は `127.0.0.1:5173`）                  |
| `npm run build`        | `dist/` への本番ビルド（圧縮、コンテンツハッシュ、ソースマップ）       |
| `npm run preview`      | 静的サーバーで `dist/` をプレビュー                                    |
| `npm run lint`         | ESLint によるチェック（`npm run lint:fix` で自動修正）                 |
| `npm run format:check` | Prettier のフォーマットチェック（`npm run format` で自動整形）         |
| `npm run check:assets` | 5 つのエントリーページが参照するローカル資産の存在と相対パスを検証     |
| `npm test`             | Vitest のユニットテストを実行（`npm run test:watch` はウォッチモード） |
| `npm run verify`       | 上記のチェックを順に実行。CI の中心的なステップと同等                  |

`scripts/dev-server.mjs` は `--root`、`--port`、`--host` オプションに対応しています。例：`node scripts/dev-server.mjs --root dist --port 4173`。

## テスト

## GitHub Actions

- **`ci.yml` — 継続的インテグレーション**：任意のブランチへの push、すべての Pull Request、および手動実行で動作します。Node.js 20 / 22 / 24 のマトリクスで `npm ci`、ESLint、Prettier チェック、静的アセットの検証、Vitest テスト、本番ビルドを順に実行し、`dist/` 配下の 5 つのエントリーページとそれぞれのハッシュ付き JS/CSS が生成されていること、HTML が正しく書き換えられていることをページごとに検証します。さらに `.nojekyll` と favicon の存在も確認し、最後に `dist/` をアーティファクトとしてアップロードします（保持期間は 7 日）。同じブランチに新しいコミットが入ると、完了していない古い実行は自動的にキャンセルされます。
- **`deploy-pages.yml` — GitHub Pages へのデプロイ**：`main` ブランチへの push または手動実行で `dist/` をビルドして公開します。初回利用時は **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選択してください。有効化するまでこの workflow は失敗しますが、CI とは独立しています。アセットの参照はすべて相対パスのため、`https://<user>.github.io/<repo>/` のようなサブパスでもサイトは正しく動作します。
- **`dependabot.yml` — 依存関係のメンテナンス**：npm の依存関係と GitHub Actions のバージョン更新を毎週チェックします。開発用依存関係の minor / patch 更新は 1 つの PR にまとめられます。

## `task-manager/` サブプロジェクト

このリポジトリには、Cloud Agent の開発環境を検証するために以前作成したフルスタックの **Task Manager**（Express + SQLite + React）も残されています。`task-manager/` ディレクトリに整理されており、独自の `package.json`、`package-lock.json`、ESLint 設定を持つ独立した npm プロジェクトです。本ゲーム集のビルド・Lint・テストには影響しません（ルートの ESLint と Prettier はいずれもこのディレクトリを無視します）。

```bash
cd task-manager
npm ci
npm run dev        # API :4000 + Web :5173
```

ゲーム集と Task Manager の Web 側を同時に動かす場合は、どちらかのポートを変更してください（例：`npm run dev -- --port 5175`）。既定ではどちらも `5173` を使用します。詳細は [`task-manager/README.md`](./task-manager/README.md) を参照してください。
